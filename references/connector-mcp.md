# 内置浏览器 Zotero Connector MCP

用于网页抓取入库、缺 PDF 时通过浏览器下载，以及桥接连接诊断。先发现当前可用工具；下面是用户桥接版 v2 的工具名，其他环境以实际能力为准。MCP 不可用不等于 Zotero 未运行，也不要擅自重装扩展或重建服务。

## 正常操作

已确认学校登录、论文身份和当前详情页 URL 时，优先 `save_and_check_pdf(title, expected_url, doi="", wait_seconds=30)`，合并一次官方保存和本机附件轮询，减少逐篇 status、save、页面读取往返。内部仍检查活动 URL 和翻译器。

已有同题名有效 PDF 时返回 `already_has_verified_pdf` 并跳过抓取；新抓取后返回父/附件 key、页数、字节、MD5 和首页片段。核对首页身份再归并原条目。`saved_pdf_pending_or_missing` 表示等待结束，查副作用后走正常页面下载，不能再次保存。最长等待 60 秒，未知结果不重放。题名末尾句点和空白可规范化，DOI 冲突不能忽略；无 DOI 时核对作者、年份和版本。旧工具仍用于诊断或分步操作：

1. 在普通网页核实该平台学校登录，并用题名、作者等确认目标论文。MCP 的 `zotero_online` 只表示 Zotero 在线，不证明学校认证或全文权限。
2. `connector_status(expected_url="")` 读取活动 HTTP(S) 网页、题名、翻译器、桥接版本和 Zotero 在线状态。正常情况下自动识别当前页；多窗口/多浏览器有歧义时，使用刚观察到的论文完整 URL 做精确匹配。不默选任意窗口，也不移除匹配检查来强行保存。
3. 状态为目标论文且已识别文献翻译器后，调用 `save_current_page(expected_url="")`，实际触发官方 Connector 保存动作。检查 Zotero 新旧条目和子附件；`save_requested` 只证明指令已发出。尚未识别翻译器时先查页面加载/阻碍，不退化成保存普通网页。
4. 给自动附件留出合理时间，通过本机查询核对，不重复保存。确认仍缺 PDF 后，调用 `download_current_pdf(expected_url=<实际活动论文完整URL>)`。它使用页面明确显示的 PDF 链接和浏览器认证，不猜测下载地址；链接缺失、多个候选或目的站点需另审查时，回到页面确认。
5. 有 `download_id` 才调用 `download_status(download_id)`；`download_requested` 或 `state=complete` 都还需检查实际文件格式、内容、字节和页数。取得 PDF 后用本机接口附到目标条目，最后核对真实存储文件。

浏览器保存可能创建新父条目。处理已有文献时，保存前记录原 key 和候选，保存后找出本次新 key；按用户授权更新或归并，保留笔记和分类，验证后清理本次重复项。不要为重试而不断制造新条目。

## v2 连接与恢复

- v2 由扩展后台连接本机服务，自动读取本机配对配置；不要求保留桥接标签页、手工填写令牌或点击 Connect。
- 用户服务通常名为 `zotero-connector-bridge`，默认连接 `127.0.0.1:23130`。先检查当前注册/进程和 `connector_status()`；诊断客户端与注册服务不能同时占用这个端口。服务重启后扩展应自动重连，先验证恢复，不反复重载扩展。
- 升级后确需重新加载扩展，且工具不能操作扩展管理页时，向用户说明目标浏览器和现有扩展，一次交代必要操作；不要绕过内部页面限制，也不要把正常网站操作一并停下。
- 从 MCP 客户端配置定位实际安装目录；只在排查服务时查看源码，不将安装目录写死。文献下载任务本身不授权修改桥接代码、权限或全局配置。
- 本机配对令牌与 Zotero 本机写入 key 是不同凭据：前者由桥接配置自动供给，后者按用户持续授权选择存入 Windows 凭据管理器，由共享客户端直接复用，详见 [local-api.md](local-api.md)。分享包排除 `.bridge-token` 和 `mcp-private-config.json`，不把配对文件、授权 key 或 Cookie 写进任务进度。

## 故障分流

| 返回或现象 | 处理 |
| --- | --- |
| 当前 URL 不匹配或候选为零 | 查实际活动标签页；页面可能已重定向到登录/验证码，不能一概判为断线 |
| 多个浏览器匹配 | 先只读确定唯一目标实例；只给该实例发送保存/下载，不广播写操作 |
| `Outcome unknown`、超时或回执丢失 | 先查 Zotero、实际下载文件和当前页面，再决定是否重试；不自动重放写指令 |
| `USER_CANCELED` | 先停自动重试，问一次是否主动取消；用户确认未取消且无安全阻断时，查副作用后可尝试正常页面下载；不将页面成功归功于 MCP 下载 API |
| 新条目无 PDF | 元数据成功、全文未完成；改用明确下载接口，而非重复抓取 |
| 下载成功但导入未完成 | 记录已验证文件/阶段，续作附加，不重新下载 |

## 验证与报告边界

验证 MCP 时分开记录：无桥接页连接、自动定位正确论文、官方保存生成真实条目、真实 PDF 落盘和附回、服务重启恢复。只在本次请求涉及 MCP 调整/验收时执行这些测试，不为每批文献重跑开发测试。

模拟浏览器 API 的测试能验证路由与协议，不能证明真实浏览器下载。需要历史验收依据时查看该项目当前验证记录；每次以实际结果为准，不把历史通过当作当前连接、权限或 PDF 成功的证据。
